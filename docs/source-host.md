# Trusted host and consumed-edition source

Construction only. No private receipts, mappings, recordings, labels, databases,
fits, statistics, reports, models or devices were accessed/executed to write this
source. G0/G1, rights and actual independent people remain pending Roy. A built
bridge supplies neither the actual evidence nor permission to execute it.

`evaluation.host` stays outside the core wheel, alongside the existing evaluator.
Its classes suppress private representations. Do not log/asdict private objects
into public output or coding-model context; only approved bounded aggregates may
leave the admitted encrypted local root. Python callbacks/closures are trusted
operator capabilities, not isolation against hostile owners or custom providers.

## Real-dev binding

`TrustedHost` requires actual canonical G0Receipt/G1Receipt and EditionPins,
operation `authorize`, uppercase `verify_receipt`, `verify_current`,
`verify_mapping`, `verify_source`, and actual approval actor/time. No permissive
implementation or default approval exists. Construction is inert.

`refresh(action,subject)` calls exact operation authorization and the existing
`admit_g0`/`admit_g1` APIs. Those use canonical `receipt_digest` subjects and require
actual host verification, including G0 again during G1. Known rights/split/runtime/
gold EditionPins must reconcile to G0; `verify_current(evidence,pins)` additionally
must inspect the ENTIRE requested code/model/runtime/config/map/threshold/video/
gold/source closure, current consent/withdrawal/private storage/offline evidence,
role ownership and chronology. A known digest, accepted AdmissionResult, declared
FitAuthorization or Attempt is never bearer authority. The external verifier must
look behind each digest at actual independent private originals, not self-sign.

TraceBinding uses the existing canonical G0 person_digest/window_digest directly,
plus actual trace bytes/provenance/native-offline/private-boundary commitments.
TraceManifest is an immutable complete split mapping, with existing canonical JSON
digest, not an identity-alias scheme. Exactly96 distinct trace/window entries must
match G0's actual split/person/scheduled positive class; no gold values enter.
Host `verify_mapping(manifest,g0,pins)` must independently reconcile actual private
source identities/bytes and the frozen mapping. Once observed, a split mapping
cannot change. A frozen dev mapping is required before held-out mapping acceptance,
and their trace sets must be disjoint. No held-out detector trace exists in the
host before the consumed extraction callback creates its manifest.

`dev_adapter(manifest,source_factory=...)` refreshes actual admission and constructs
FitAuthorization from canonical G0/G1, rights/roster and exact eight dev people.
Current remaining EditionPins stay bound in the host closure, since the existing
FitAuthorization schema does not contain code/config/gold/source fields. Its
CounterAdapter verifier refreshes action `host.source.dev` on every window access,
revalidates the frozen mapping, invokes actual source-byte/evidence verification,
then returns exact SourceAdmission. It receives no labels. Factory opening follows
verification. Provider must retain PrivacyPolicy/DeviceAuthorization checks and
canonical/revalidated paths; neither copied hashes nor a callback name prove those
checks. No synthetic or held-out row can enter this real-dev callback.

## One-shot held-out source

`CustodianEdition` requires an actual CustodyStore/TrustedHost/PrivacyPolicy,
explicit private artifact directory, independent-operator receipt and required
prediction/gold verifier callbacks. Its `run` requires extractor, concrete
FrozenAllArmPredictor and gold loader. All callbacks remain unavailable until an
actual authorized local host supplies them. No fake capability is installed.

1. Refresh host and predictor frozen closure BEFORE reservation/acquisition.
   Reserve exactly ALL_ARMS with actual EditionPins and AdmissionEvidence through
   CustodyStore's own verifier/authorizer. Starting the in-process run disables
   retry; a committed edition remains consumed on every later failure/crash.
2. `extract_once` commits extracting before calling the actual extractor. The
   extractor acquires/persists traces once, returning a complete held-out manifest
   whose canonical hash becomes the custody trace commitment. It must retain
   existing acquisition/rights/private/offline guards; no held-out inference may
   precede reservation. The orchestrator does not inspect real data in this task.
3. FrozenAllArmPredictor opens each acquired trace once and dispatches identical
   geometry/evidence through existing Counter implementations. Its separate
   HeldoutSourceAdmission requires a fresh callback checking exact consumed attempt,
   pins, extracted state, trace manifest, current permission/consent/withdrawal and
   actual source evidence BEFORE the SourceFactory opens. No bare attempt token or
   real-dev FitAuthorization grants held-out access. Providers retain per-access
   guards/withdrawal cancellation; synchronous Python cannot preempt native calls.
4. Exactly96 windows for ALL6arms, unchanged keys/trace hashes, config identities,
   statuses/counts/features and prior emissions are retained. Required external
   `verify_predictions` reconciles these actual outputs against the frozen protocol
   and current complete pins, not against gold. Missing arms/windows reject instead
   of shortening scheduled exposure or inventing zero results.
5. The host writes a bounded16MiB create-only private envelope with exact
   attempt_id/pins_hash/trace_hash/arms fields, flush/fsync, then calls actual
   `seal_predictions`. Existing/partial artifacts are never overwritten/deleted.
6. Only `join_gold_once`'s post-seal callback can call the gold loader. Fresh host
   and independent-operator permission precede that access. Sealed bytes/hash must
   exactly match the immutable prediction records. Actual gold verifier reconciles
   the pinned private originals and complete96 labels. Existing `from_prediction`
   performs the typed identity join; no metric/statistic is reimplemented.
7. The actual FrozenSchedule/runner canonical prediction and gold seals are built
   with existing methods, then `run_evaluation` produces aggregate-only ResultBundle.
   Custody byte SHA256 and runner semantic seals are intentionally DIFFERENT named
   commitments; the exact-byte check binds the latter records to the former seal.
   The report bundle's actual canonical hash is recorded by join_gold_once. Claim
   gates default unavailable; a supplied ClaimGates needs a separate required host
   verifier against actual schedule/pins before existing claim selection runs.
8. `rerender(renderer)` gives only the retained immutable aggregate ResultBundle to
   a renderer and requires the exact same report hash through actual custody checks.
   It never calls extractor/predictor/gold again. No evaluation recovery or retry
   is provided: a fresh host must not reevaluate a consumed
   edition. The separate completed-report restoration below reloads only an
   already completed immutable aggregate for rerender.

## Frozen A2 and unavailable paths

FrozenAllArmPredictor uses the existing PipelineResult, parameter-grid adapter,
Counter/GeometryAdapter/attach_evidence and MapArtifact.probability. No duplicate
detector/calibrator/math or held-out refit exists. A required `verify_frozen` checks
actual frozen OOF/final artifacts and full current protocol/code/model/source closure
before reservation; canonical config/map/threshold roots must match EditionPins.
The defined freeze encoding uses canonical_digest over ordered final-config asdicts,
final-map as_dict (or explicit null artifact), and {a2,a0v} OperatingPoint asdicts.
Those are explicit artifact identities, never consent or signature claims.

A2 additionally needs all8 available outer maps with exact seven-person scopes,
the matching OOF prediction seal, final map trained on dev people, valid actual
selected operating point, and matching map model/runtime/split/counter pins.
Its probability comes only from existing MapArtifact.probability. A2 reuses the
same gated events/features as A2-H and applies the frozen whole-window threshold;
confidence refusal retains prior emitted exposure. Missing OOF/final-map/policy
qualification yields an explicit A2 not_run payload (or error for source errors),
null final count/probability, no A2 emissions; A2-H remains separate. Unavailable
A0v policy remains explicit, not silently selected on held-out results. No manual
threshold is called calibration. Independent checks must validate the complete
OOF/final artifacts behind the matching digests; source assertions do not prove fits.

## Completed-report restoration after process restart

`CompletedReportRoot` is an externally established owner root: exact persisted
Attempt/EditionPins, trace commitment, custody prediction-envelope BYTE SHA256,
runner semantic prediction `source_seal`, and expected aggregate report hash.
It is never loaded from the untrusted JSON being checked. The report hash is the
existing `bundle_hash` identity, not a new hash format. The two prediction seals
are intentionally different definitions. Required `verify_completed(root,summary)`
must independently verify their actual relationship, complete scheduled-window
identity/census and the current code/model/runtime/config/map/policy/rights closure
against authoritative private owner records. A copied digest, AdmissionResult,
Attempt or approval flag cannot establish that external root. No verifier or
actual evidence is supplied here.

`CompletedReport.restore(host=...,custody=...,privacy=...,root=...,
aggregate_path=...,verify_completed=...)` is the sole file-read entry point. It:

- Freshly authorizes `host.edition.restore` on the attempt ID and invokes the actual
  current host G0/G1/current-pin checks. Current EditionPins must equal the root.
- Calls existing `CustodyStore.summary` to resolve that exact persisted Attempt.
  It requires complete, nonwithdrawn state and matching attempt/pins/trace/
  prediction-byte/report hashes before reading the supplied aggregate. Incomplete,
  crashed, unknown, invalidated, stale or mismatched state refuses access.
- Calls required external completion-root verification, existing PrivacyPolicy on
  the exact supplied aggregate path, then `host.report.read` authorization on its
  canonical private path. No directory scan, automatic newest-file selection,
  source/gold read or database reconstruction is implemented.
- Reads at most4MiB+1 bytes, requires exact original SHA256 against the external
  expected report root, then calls the existing strict
  `posecount.report.load_bundle_json(...,expected_bundle_hash=...)`. No schema or
  loader is duplicated. Bytes must equal existing canonical_json output exactly:
  reformatted/BOM/trailing/changed payloads reject, never silently normalize into
  another report. Missing/oversized/partial/tampered/unknown input rejects.
- Requires measured original real/held_out, all6arms, exact edition_hash from the
  existing results_writer helper, matching semantic source seal, and scheduled
  people/window/positive/negative support matching the current admitted G0 census.
  Original comparison identity must also match. Null/unavailable measured outcomes
  remain unchanged; an empty/unmeasured/incomplete shell cannot become a completed
  study or host success. Actual exact window linkage remains the required owner's
  completion-root verification obligation, not something inferred from counts.
- Rechecks current host/custody/root authority after the read and retains only the
  validated immutable bytes. It never resumes the evaluation state machine.

`CompletedReport.rerender(NEW_DIRECTORY)` rechecks current authority and rehydrates
the same retained bytes with the same loader/root checks. It uses existing Windows
plain-path/no-link rules, a fresh output directory, `host.report.write` authorization
on that destination, and actual `write_artifacts` with the unchanged expected bundle
hash. Existing files/directories reject. Only aggregate data reaches the writer.
The callback runs through existing CustodyStore.rerender, preserving its current
completed/withdrawal/prediction-byte-seal/report identity checks before and after
rendering; the new binding additionally rechecks actual host/root state around
the writer. Custody's existing internal prediction-seal checks do not expose or
rehydrate private predictions in this binding. No source, gold, tuning, fitting,
statistics, number recalculation or mutable schema reconstruction occurs.

The restored object has no run/extract/predict/gold/retry/resume API. A failed or
withdrawn write leaves any partial artifacts for owner disposition; nothing is
overwritten/deleted or retried. Later source-file tampering does not mutate already
retained pinned bytes; a new restore rejects changed bytes. Concurrent hostile
filesystem/owner behavior and cancellation of an already-running native callback
remain trusted-operator/runtime boundaries. Required host callbacks enforce current
roles, consent/withdrawal, canonical private roots and the actual external expected
root; no name/hash alone proves them. This source performs no actual file/database
read or rendering during construction.

Deferred execution: completed versus partial/withdrawn/stale/unknown state; external
root and current-map/edition/semantic-vs-byte seal linkage; private path authorization
before reads; duplicate/unknown/BOM/reformatted/oversized/tampered JSON; original
all-arm census and null outcomes; strict hydration/unchanged report hash; exclusive
output, partial writes and withdrawal races; no reevaluation on restart. No tests,
imports, SQLite, private records, reports or renderer were run to construct this.
