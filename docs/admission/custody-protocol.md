## Open-once all-arm sequence

1. Verify authorized private/offline boundaries, exact rights and source/code/model/runtime/config/map/threshold pins, and predeclared arms. Failed preconditions BEFORE reservation are not attempts; preserve the reason, never read held-out detector inputs while checking.
2. Before ANY detector-held-out video, trace OR gold read, atomically reserve one all-arm attempt in future SQLite custody with a UNIQUE edition key. Record timestamp, code commit, model/runtime/config/map/threshold hashes and video/gold seal commitments. One committed reservation consumes the edition, even if the next operation crashes. Concurrency must not admit two attempts for one edition.
3. Only after successful reservation, independent operator extracts all held-out traces once on the canonical pinned runtime, records trace hashes and runs all predeclared arms on identical traces. No per-device held-out re-extraction, selected-arm rerun, fallback model or hidden retry. Preserve partial artifacts and failure state on errors.
4. Seal predictions and their hash BEFORE joining gold. Actual gold join/scoring occurs only in the independent custodian/scorer channel; no unsealed prediction adjustment, builder individual-gold read or later tuning.
5. Generate reports from the immutable sealed predictions. Rerendering those records without model reevaluation is allowed; it must preserve numbers and provenance, not reopen an attempt. All failures, nulls and support remain visible.

No reset/recovery/reopen flag can restore an edition. A post-reserve crash consumes it; preserve its identity and partial state. A new headline requires new unseen people/edition and Roy authorization. Do not relabel a rerun or withdrawal-adjusted recomputation as unseen evaluation.

## Native operator and withdrawal boundary

For later private extraction/camera work, operator first approves impact on other sessions; records/disconnects all active Wi-Fi/Ethernet/cellular/VPN interfaces and verifies offline state. Run only the approved process, close it before restoring prior network state, preserve receipt. Unverified offline state stops private-data use. No settings or interfaces are changed now. This proves only observed outbound transport unavailable during the measured run; queued telemetry/vendor internals are unaudited.

Repeated device/latency extraction uses dev footage only, on two named physically different machines; it cannot create repeated held-out extraction. Source/runtime deviations need the plan's recorded authorization, never an unrecorded sealed-edition change.

Withdrawal immediately stops affected use, deletes person rows/derivatives through the actual private owner and invalidates the sealed edition/claims. Record deletion and issue a nonidentifying notice; historical aggregates remain only where retention rights permit, otherwise withdrawn. Proposed raw-video<=90days and trace/label<=180days after closeout require actual acceptance. Retain audit commitments only to the extent permitted by those rights, not raw private data for convenience.
