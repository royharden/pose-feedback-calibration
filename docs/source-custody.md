## Authority and trust boundary

All effectful APIs require an injected trusted-host `authorize(action: str, subject: str) -> bool`; only exact True grants. No default policy, `signed=True`, receipt-as-credential or secret is embedded. Trusted independent operators retain private originals; builders receive only bounded aggregate counts, hashes and fixed failure codes. Private dataclasses suppress repr; callers must also avoid logging private objects/paths/free text. An externally supplied callback can lie, and a local database/file owner can bypass the code: this is a trusted-operator audit convention, not hostile-operator isolation or proof of human independence. Permission callbacks must enforce actual role ownership, freshness, blind annotation, no held-out tuning and current consent/withdrawal status.

Admission uses a separate `verify_receipt(stage: str, digest: str) -> bool` callback. That host must compare actual private human/signature/rights/chronology records and the ENTIRE referenced pin closure, not accept a known-looking digest or builder-made object. Stage strings are uppercase G0/G1; authorize actions admission.g0/admission.g1 use the exact canonical receipt hash as subject. Unsigned validation always reports accepted=False, even for structurally complete receipts.

## Fixed split and support

`evaluation.split.AdultMetadata(person_digest, capture_class, adulthood_evidence_digest)`, `Assignment(person_digest,capture_class,split)` and `SplitCommitment(roster_digest,assignments,digest,seed=17012026)` are frozen private structures. `freeze_split(roster_tuple)` accepts exactly16 distinct existing adults represented by digest commitments; it does not recruit or author a roster. The roster must contain exactly eight phone and eight webcam captures. Canonical roster/hash-ranked stratification using the fixed seed produces exactly eight dev/eight heldout, each with four phone and four webcam captures. `validate_split(roster,split)` compares the entire frozen result; there is no seed choice, migration or adaptive replacement operation. Alternative capture distributions that cannot meet this exact source policy are unavailable, not silently balanced differently. Host must verify roster freeze preceded detector outputs.

`evaluation.admission.RoleEvidence(custodian_digest,annotator_a_digest,annotator_b_digest,builder_digests,final_verifier_digest)` requires independent custodian/A/B/final verifier relative to builders, A!=B, final verifier one of A/B; custodian/A overlap remains allowed. Hashes alone cannot prove those people or duties.

`WindowSupport(window_digest,person_digest,kind,view,condition,duration_seconds,jointly_scoreable)` feeds `G0Receipt(roster,split,roles,physical_machine_digests,windows,pins)`. All192 unique windows must be >=32s,12/person: six positives=front/45/side x ordinary/obstructed; six ordinary negatives stand_talk/walk_twice/sit_stand/pickup/wave/exit_reenter. At least90% jointly scoreable windows are required separately for each96-window split. Positive support for each person/view/condition is explicit; summary also exposes split/view support without raw identities or labels. Two distinct physical-machine commitments and a complete fixed pin closure are required.

G0 pin names: roles, consent, machines, private_root, offline, rubric, roster, split, source, gold, rights, runtime, ordering, retention_withdrawal, budgets, independent_manual_cases. Roster/split pins reconcile to the derived commitment. Consent pin must resolve to16 actual signed adult consents; role, private-root/offline, rights, machine, pre-capture human-rubric/CSV freeze and ordering duties remain host-verification obligations. Digests are byte identities, not signatures or consent. No fake receipts are supplied.

`validate_g0(receipt)` is structural unsigned preparation only. `admit_g0(receipt, *, verify_receipt, authorize)` additionally requires actual host verification and permission. `AdmissionResult(accepted,stage,pins,counts,reasons)` contains bounded aggregate counts and a receipt hash, never private rows and NEVER bearer authority.

`G1Receipt(g0_digest,source_digest,split_digest,rights_digest,gold_digest,import_digest,original_blind_votes_digest,adjudication_digest,heldout_custodian_agreement_digest,dev_agreement)` uses private `BlindAgreement(window_digest,jointly_scoreable,exact_count_agreement)` rows. All96 dev identities/statuses must match G0; mutually scoreable original blind rows form the exact-agreement denominator, others require unknown agreement. Require numerator/denominator>=0.80, per-split G0 quota intact, source/split/rights/gold pins reconciled. Actual imported CSV hashes, blind-original/adjudication evidence and held-out agreement are independently checked through host closure verification; held-out agreement never tunes dev. `validate_g1(receipt,g0)` cannot admit; `admit_g1(...,verify_receipt,authorize)` freshly verifies both actual G0 and G1. Failed/unknown gates remain failed, no result object can self-sign.

## Private labels and append-only revisions

`labels.LabelSource(expected_windows, schema_sha256, policy, journal_directory, authorize)` is inert. `expected_windows` maps IDs to frozen `WindowSpec(source_sha256,movement,split)`; these and the supplied schema pin contribute to dataset identity. Existing privacy.PrivacyPolicy is read-only dependency; every future input/output open validates its canonical boundary. No real files are opened in this task.

Exact CSV header order is window_id,annotator_code,source_sha256,movement,return_media_timestamps,count,scoreable,notes,revision. Return timestamps are a strict JSON numeric array; duplicate/nonfinite JSON and unexpected columns reject. Booleans use true/false; original revision0 only. Each A/B file covers every expected window exactly once with exact source/movement pins. Count must match increasing observed return timestamps in[3,30); unscoreable requires null/empty count and no timestamps, never an invented zero. Original source-time cycle-start interpretation still requires the pre-frozen independent human rubric; software cannot infer unseen starts from return rows.

`import_csv(path, *, annotator, expected_sha256)` retains original immutable BlindVote rows. `freeze_blind()` requires both complete original imports before changes. `adjudicate(window_id, *, count,scoreable,return_media_timestamps,reason)` appends immutable Revision(old,new,revision,reason), requiring separate labels.adjudicate.A AND .B plus custodian authority; no original vote is overwritten. Equal count AND timestamps establish original consensus, otherwise Decision remains unresolved/unscoreable until actual joint adjudication. Readers original_votes(split), resolved_votes(split), revisions() require labels.read, custodian-or-scorer authority AND explicit labels.read.dev/heldout; revisions requires both split reads. Builders have no label permission by default. summary() exposes only LabelSummary counts/frozen/sequence/journal/dataset hashes.

Other actions: labels.import.A/B, labels.freeze, labels.custodian, labels.journal.write/restore, labels.summary. Subject is dataset digest except joint A/B adjudication checks use window ID. Independent host must verify frozen schema approval, actual blindness and genuine joint consent; code permissions do not certify human actions.

Every mutation writes a create-only full private snapshot labels-NNNNNNNN.json, flushes/fsyncs before installing in-memory changes, preserves old snapshots and never deletes/overwrites. Failed/partial file leaves a blocked sequence for owner disposition. `restore(path,expected_sha256,expected_sequence)` requires externally pinned latest digest/sequence, validates the whole snapshot and replayed old/new chain; no latest-file scan or rollback assumption is made. Snapshot store is limited to4MB,1024 expected windows,4096 rows/revisions,2048-char cells and256 returns. Exclusive creation makes concurrent conflicting writers fail closed; host must serialize the journal and keep trusted latest pins. Directory-fsync/platform durability, private-path TOCTOU and restart behavior are unverified.

## Edition and reservation APIs

`custody.EditionPins(code_commit,model_hash,runtime_hash,config_hash,map_hash,threshold_hash,video_hash,gold_hash,split_hash,rights_hash,source_hash)` requires lowercase40hex commit and64hex commitments. An unavailable map/arm needs a pinned explicit unavailable artifact/status, not a fabricated fitted map or omitted arm. `AdmissionEvidence(g0_hash,g1_hash)` is declarative only. `CustodyStore(path, *, privacy, authorize, verify_admission, study_id)` opens nothing; `initialize()` is an explicit future create-only SQLite setup operation with custody.initialize permission. Existing/partial stores are preserved, never repaired/reset/deleted.

The required `verify_admission(evidence,pins)->bool` host callback independently checks actual G0/G1 records against the REQUESTED code/model/runtime/config/map/threshold/source/split/rights/video/gold closure. It must not treat an AdmissionResult or declared receipt hash as a reusable credential. This is separate from operation permission. Actual consent/rights/offline and split/label access conditions must remain current at each authorized action.

`reserve(edition,pins,admission,*,arms=ALL_ARMS)->Attempt` checks permissions and full actual admission before opening a reservation transaction. ALL_ARMS is fixed Z/A0/A0v/A1/A2-H/A2; future policy rows/statuses live inside those explicit payloads. `BEGIN IMMEDIATE`, primary-key unique edition and unique attempt identity commit one reservation atomically before any held-out detector callback. Failed preconditions before reservation do not create an attempt; a committed reservation consumes the edition forever, including crashes. Existing attempts cannot be reset/reopened/recovered or reassigned a new attempt ID.

`Attempt(edition,attempt_id,pins_hash)` is identity only. `_row` verifies its match to durable pins. Private SQLite stores pinned JSON, transitions and append-only commitment events; immutable-identity/no-event-update/no-delete triggers reinforce the API. They do not protect against a hostile file owner. summary(attempt) exposes only CustodySummary attempt/state/pin/trace/prediction/report hashes and withdrawn flag, behind custody.summary permission.

## One extraction, seal-before-gold and rerender identity

`extract_once(attempt, extractor: ()->trace_hash)` first commits reserved->extracting; only then may the independently authorized callback read detector-heldout video/traces. Successful callback returns a trace commitment, then state extracted. A failure, crash or lost storage acknowledgement never reopens extraction; started state remains consumed. No device-specific heldout re-extraction or hidden retry.

`seal_predictions(attempt,path)->seal_hash` consumes extracted->sealing and reads at most16MiB from an authorized private artifact. Exact JSON envelope fields: attempt_id, pins_hash, trace_hash, arms. arms is an object with all six exact ALL_ARMS keys and nonnull payloads; unavailable/error arms must be explicit, not missing. Identity/trace pins must match reservation/extraction. Custody checks envelope/identity, not semantic correctness of arm predictions; later evaluator validates individual outputs. It creates sealed-<attempt_id>.json exclusively, flushes/fsyncs and records byte SHA256 before sealed state. Existing/partial seals are never replaced/deleted; failure consumes the attempt. No gold callback is reachable before this sealed state.

`join_gold_once(attempt, scorer: (sealed_prediction_path)->report_hash)` commits sealed->gold_joining, verifies sealed byte identity and only then invokes the trusted custodian/scorer callback. Host must verify pinned gold bytes and scoring protocol in that callback; it may not leak individual gold to builders. Completion records immutable report hash. Errors/crashes consume; no gold-join retry. Every later artifact read verifies private boundaries and seal digest. No model/data callback is invoked during this task.

`rerender(attempt, expected_report_hash, renderer: (sealed_prediction_path)->report_hash)` permits only completed, nonwithdrawn identity with matching stored report/seal. Callback must render ONLY immutable sealed predictions/previous sealed results, no inference/re-extraction/new gold access. It must reproduce the exact report commitment; post-callback seal/withdrawal checks reject changed state. This is the same consumed attempt, never an unseen test. Opaque callbacks require trusted operator discipline; they are not a sandbox. Operator must serialize/cancel in-flight private callbacks on withdrawal; state checks stop subsequent operations/results but cannot preempt an already-running external function.

## Withdrawal without deletion

`PrivateDerivative(path,sha256,category,person_commitment)` and `plan_withdrawal(attempt, *, request_hash,inventory_hash,person_commitment,inventory,verify_inventory)` are private operator APIs. Authorized withdrawal invalidates edition/report FIRST, even if inventory planning later fails. It never restores a consumed edition. Complete inventory must cover video, traces, labels, consent/mapping, all journal/snapshot/cache/prediction/report derivatives, including mixed-person artifacts that require owner-selected redaction/replacement handling. No filesystem discovery scans are implemented.

Inventory is bounded4096 entries, canonical validated private paths with digests/categories and matching person commitment; inventory_hash commits the ordered JSON array of [canonical_path,sha256,category]. `verify_inventory(request_hash,inventory_hash,inventory)->bool` must confirm the actual withdrawal and complete private provenance inventory. Returned repr-suppressed WithdrawalPlan lists DeletionItems and always deletion_performed=False/report_status=withdrawn_invalidated. Code only records proposed deletion manifest/hash; no unlink/remove/DELETE data operation exists. Actual owner authorization/receipt is needed to delete/redact ALL affected private derivatives. Nonidentifying withdrawal notice and retention-permitted historical aggregates require later owner handling; any recomputation is withdrawal-adjusted, never a new unseen evaluation. No actual deletion plan or private path is authored in this task.
